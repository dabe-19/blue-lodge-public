# Blue Lodge LoRA training kit

This folder was generated by the Model Workbench **Train** tab (or `/models train-kit`).
It is a small, self-contained supervised fine-tuning (SFT) recipe for the base model in `config.json`.

Blue Lodge does **not** train for you. Training needs a GPU training stack (PyTorch, Transformers, PEFT, TRL),
which the lodge does not install. Run this kit wherever you train: a local CUDA box, Colab, or a rented GPU.

## 1. Environment

```bash
python -m venv .venv && source .venv/bin/activate
pip install "torch>=2.3" "transformers>=4.45" "peft>=0.12" "trl>=0.11" "datasets>=2.20" accelerate
pip install bitsandbytes            # optional: 4-bit QLoRA on CUDA (config: load_in_4bit)
huggingface-cli login               # only if the base model is gated
```

If you move the kit to another machine, copy the dataset files too and update `train_file` / `val_file`
in `config.json`.

## 2. Check, then train

```bash
python train_lora.py --config config.json --dry-run   # loads data + tokenizer, prints one formatted sample
./run.sh                                              # trains; writes output/adapter
```

The important knobs live in `config.json`:

| Key | Meaning |
|-----|---------|
| `base_model` | Hugging Face id of the **unquantized** model your GGUF was made from |
| `epochs`, `learning_rate` | Training length and step size |
| `lora_r`, `lora_alpha`, `lora_dropout` | Adapter capacity and regularisation |
| `max_seq_len` | Longest sample, in tokens. Longer samples are truncated |
| `batch_size`, `grad_accum` | Effective batch = batch_size × grad_accum |

## 3. Bring the adapter back to Blue Lodge

```bash
python <llama.cpp>/convert_lora_to_gguf.py output/adapter --base <local copy of base_model> \
       --outtype f16 --outfile my-adapter.gguf
mv my-adapter.gguf "<adapter_gguf_dir from config.json>"
```

Open **Models → Library** and the adapter appears under *Adapters*. Use **Serve & Tune → Adapters** to
attach it to a profile built on the same base model, set the scale, re-approve, and activate.

> A LoRA only works on the base model (architecture and size) it was trained on. Check the
> adapter's *base* field in the Library against the model you serve.
